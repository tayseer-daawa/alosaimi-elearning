# Routing

[← Back to student app docs](./README.md)

TanStack Router, file-based. `src/routeTree.gen.ts` is generated by the Vite plugin on
`npm run dev` — never edit it, and restart the dev server if routing behaves strangely
after you add or rename a file.

---

## The route tree

```
src/routes/
├── __root.tsx                          <Outlet /> + lazily loaded devtools
├── router.ts                           createRouter + the type registration
├── _layout.tsx                         AUTH GUARD — every page sits under this
└── _layout/
    ├── index.tsx                       /
    ├── welcome.tsx                     /welcome
    ├── login.tsx                       /login
    ├── signup.tsx                      /signup
    ├── forget-password.tsx             /forget-password
    ├── reset-password.tsx              /reset-password
    ├── example.tsx                     /example  (template debt — do not copy)
    └── programs/
        ├── index.tsx                   /programs
        └── $programId/phases/
            ├── index.tsx               /programs/$programId/phases
            └── $phaseId/books/$bookId/
                ├── index.tsx           …/books/$bookId
                └── courses/$courseId/
                    └── index.tsx       …/courses/$courseId
```

The learning path mirrors the domain hierarchy exactly:

```
/programs/$programId/phases/$phaseId/books/$bookId/courses/$courseId
```

`_layout` is a **pathless** route — it adds no URL segment. Its only job is to put every
page behind one `beforeLoad` guard. Anything placed outside `_layout/` is unprotected.

`/example` is a live route, not a scratch file: it mounts `src/features/example/`, whose
code contradicts the constitution. See
[feature-status.md](./feature-status.md#reference-code-that-is-wrong).

## Adding a route

Route files stay thin. Create the file, import the screen, mount it. No logic here.

```tsx
// src/routes/_layout/programs/index.tsx
import { createFileRoute } from "@tanstack/react-router"
import ProgramsScreen from "@/features/programs/components/ProgramsScreen"

export const Route = createFileRoute("/_layout/programs/")({
  component: ProgramsScreen,
})
```

The path string must match the file's location — the plugin writes it for you when the
dev server is running.

## Navigating

Use typed params, never string interpolation:

```tsx
const navigate = useNavigate()

navigate({
  to: "/programs/$programId/phases/$phaseId/books/$bookId",
  params: { programId, phaseId, bookId },
})
```

`params` values are strings. Fixtures currently supply `"1"`; real data supplies UUIDs.

## Reading params

Screens read params loosely because they are mounted from several depths:

```tsx
const { programId, phaseId, bookId } = useParams({ strict: false })
```

`strict: false` gives you `string | undefined` rather than a compile error when a param is
not present on the current route. Handy, but it means the compiler will not catch a typo —
check the value before using it.

## Reading search params

```tsx
const search = useSearch({ strict: false })
const token = typeof search.token === "string" ? search.token : undefined
```

Used by `/reset-password`, whose token arrives in the emailed link.

## Breadcrumbs

`@/shared/components/BreadcrumbsNavigation` renders the trail. Mobile only —
`display={{ base: "flex", lg: "none" }}` — because desktop shows a centred page heading
instead.

```tsx
<Breadcrumbs
  breadcrumbs={[
    { label: `البرنامج ${programId}`, url: "/programs" },
    { label: "المراحل", isCurrent: true },
  ]}
/>
```

A crumb may also carry `hasDropdown` with an `options` array, which renders a Chakra menu.
The course screen uses this for the `المقرر` selector — its options are currently
hardcoded.

## Code splitting

`autoCodeSplitting: true` in `vite.config.ts`. Every route is split automatically; do not
add manual `React.lazy` around screens.
