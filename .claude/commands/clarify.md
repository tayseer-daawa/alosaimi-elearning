description: Resolve the open questions in a spec by asking, one topic at a time
argument-hint: <issue number>
---

Resolve every `[NEEDS CLARIFICATION]` marker in `specs/$ARGUMENTS-*/spec.md`.

Steps:

1. Read the spec. List the markers.
2. **If `docs/api-map.md` does not exist, stop** and tell the user — it is generated by the
   backend and has not landed yet. Do not answer endpoint questions from the generated
   client or the backend routes instead.
3. Before asking, check whether the answer is already in the repository — `docs/domain.md`,
   `docs/api-map.md`, an ADR, the backend models, an existing slice. Resolve from evidence
   where you can, and say what evidence you used.
4. Ask the user about what remains. **Short, plain questions, a few at a time.** Offer
   concrete options with their consequences where a choice exists; do not present an
   open-ended essay question.
5. Update the spec in place: remove the marker, fold the answer into the requirement or
   scenario it belonged to. Add a requirement id if the answer created a new obligation.
6. If an answer contradicts `docs/constitution.md`, say so and stop. That needs an ADR, not
   a quiet exception.

Done when zero markers remain. Set Status to `Clarified`, report what changed, and remind
the user this is the moment to open the specs pull request so the spec is reviewed before
the plan is written.
